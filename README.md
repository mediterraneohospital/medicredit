# MediCredit v1 — Mediterraneo Hospital

Ανεξάρτητη web εφαρμογή Τμήματος Προμηθειών για περικοπές **υλικών** από επιτροπές διαιτησίας και παρακολούθηση πιστωτικών. Δεν περιέχει σύνδεση, κλειδιά ή δεδομένα MediPrice.

## Άμεση εκκίνηση

Απαιτείται Node.js 22 ή νεότερο. Μέσα στον φάκελο του project:

```sh
node server.mjs
```

Ανοίξτε **http://127.0.0.1:4173**. Δεν χρειάζεται εγκατάσταση πακέτων ή build. Εναλλακτικά `npm start`.

Η εφαρμογή λειτουργεί αποκλειστικά με το ανεξάρτητο Supabase project του MediCredit και απαιτεί είσοδο εξουσιοδοτημένου χρήστη.

## Νέο ανεξάρτητο Supabase

1. Δημιουργήστε **νέο, άδειο Supabase project**, π.χ. `mediterraneo-medicredit`, με κατάλληλη ευρωπαϊκή περιοχή φιλοξενίας. Μη χρησιμοποιήσετε το project του MediPrice ή άλλης υφιστάμενης εφαρμογής.
2. Στον SQL Editor του **νέου** project εκτελέστε ολόκληρο το `supabase/migrations/20260929060604_initial_medicredit.sql` μία φορά. Το migration εκτελείται σε transaction και δημιουργεί tables, validation trigger, atomic save RPC, RLS και ιδιωτικό Storage bucket.
3. Στο Authentication απενεργοποιήστε public signups και anonymous sign-in. Δημιουργήστε τους εγκεκριμένους χρήστες από το διαχειριστικό Authentication με email/password. Στο v1 η είσοδος γίνεται με ήδη ενεργό λογαριασμό· δεν υπάρχει self-registration ή φόρμα ανάκτησης κωδικού.
4. Για κάθε εγκεκριμένο χρήστη αντιγράψτε το UUID του από Authentication και εκτελέστε ως διαχειριστής:

```sql
insert into public.mc_members(user_id) values ('UUID-ΧΡΗΣΤΗ');
```

   Οι ενεργοί χρήστες του Τμήματος έχουν κοινή πρόσβαση ανάγνωσης/επεξεργασίας. Η απλή ύπαρξη λογαριασμού Auth **δεν** δίνει πρόσβαση στα δεδομένα. Για ανάκληση:

```sql
update public.mc_members set active = false where user_id = 'UUID-ΧΡΗΣΤΗ';
```

5. Στο `config.js` συμπληρώστε το URL και το **publishable key** του νέου project:

```js
export const config = {
  mode: 'supabase',
  supabaseUrl: 'https://NEW_PROJECT_REF.supabase.co',
  publishableKey: 'sb_publishable_...'
};
```

   Μην τοποθετήσετε `service_role`, secret key ή κωδικό βάσης στο frontend. Τα δικαιώματα ελέγχονται από τη βάση, όχι από το UI.
6. Βεβαιωθείτε ότι το Data API είναι ενεργό για το `public` schema. Το migration δίνει ρητά τα απαιτούμενα grants. Το όριο επιστρεφόμενων σειρών του API να είναι τουλάχιστον **500** (ο client διαβάζει σε σελίδες των 500).
7. Ανανεώστε τη σελίδα και συνδεθείτε. Η βάση ξεκινά κενή.
8. Δοκιμάστε με πλασματικό περιστατικό την αποθήκευση, αποσύνδεση/επανασύνδεση και την αποθήκευση/ανάγνωση PDF. Αυτός ο τελικός έλεγχος στο δικό σας live project είναι απαραίτητος: η παράδοση ελέγχθηκε τοπικά χωρίς να δημιουργηθεί ή να συνδεθεί cloud project.

### Φιλοξενία frontend

Είναι στατικό HTML/CSS/JavaScript με ES modules. Δημοσιεύστε **μόνο** `index.html`, `config.js` και `src/` σε νέο ανεξάρτητο repository/site με HTTPS (π.χ. GitHub Pages). Τα σχετικά paths επιτρέπουν λειτουργία και σε υποφάκελο. Μη δημοσιεύσετε δείγματα ασθενών, SQL εξαγωγές ή credentials. Ο τοπικός server δεσμεύεται μόνο στο `127.0.0.1` και δεν προορίζεται για production hosting.

Το `server.mjs` προσθέτει CSP, no-store και nosniff headers. Σε άλλο hosting προσθέστε αντίστοιχα headers όπου υποστηρίζονται. Δεν χρησιμοποιούνται CDN, εξωτερικές γραμματοσειρές, analytics ή frontend dependencies.

## Χρήση

1. **Εταιρείες:** καταχώρηση επωνυμίας, υπευθύνου, email και σημειώσεων.
2. **Νέο περιστατικό:** κωδικός νοσηλείας, ασθενής, ιατρός, ξεχωριστή ημερομηνία περιστατικού, ημερομηνία επιτροπής, τύπος περικοπής, προαιρετικό PDF απόφασης και σημειώσεις. Η ημερομηνία περιστατικού δεν μπορεί να είναι μεταγενέστερη της επιτροπής.
3. Προσθέστε εταιρείες και κόστος υλικών. Δηλώστε συνολικό κόστος `C` και αναγνωρισμένο ποσό `P`.
4. Για **Plafond** υπολογίζονται αυτόματα `C−P`, κοινό ποσοστό και προτεινόμενο πιστωτικό ανά εταιρεία. Το κουμπί **Πρόταση → ποσό αιτήματος** αντιγράφει την πρόταση μόνο στις εταιρείες που παραμένουν «Προς αίτηση». Επεξεργαστείτε το ποσό αιτήματος όπου χρειάζεται. Η πρόταση παραμένει χωριστή.
5. Για **Συγκεκριμένα υλικά / Άλλο** καταχωρίστε χειροκίνητα τις επιμέρους προτάσεις. Το άθροισμά τους πρέπει και πάλι να ισούται με `C−P`.
6. Επιλέξτε **Ζητήθηκε** και ημερομηνία αιτήματος. Στη μερική παραλαβή καταχωρίστε ποσό, ημερομηνία και αριθμό πιστωτικού, κρατώντας «Ζητήθηκε» όσο αναμένεται υπόλοιπο. Επιλέξτε «Παραλήφθηκε» όταν ολοκληρωθεί η ανταπόκριση της εταιρείας.
7. Αν η διεκδίκηση σταματήσει με ανεξόφλητη διαφορά, συμπληρώστε **Αιτιολογία κλεισίματος**. Για επαναφορά αδειάστε την αιτιολογία.
8. Για αλλαγή υπάρχοντος περιστατικού, πατήστε **Επεξεργασία** στη γραμμή του ή τον κωδικό νοσηλείας. Το φίλτρο εφαρμόζεται στην **ημερομηνία περιστατικού**. Πατήστε το αριστερό μπλε πλήκτρο για εναλλαγή `Y` (έτος), `M` (μήνας), `D` (ημέρα) και `−` (όλες οι ημερομηνίες). Τα βέλη μετακινούν την επιλεγμένη περίοδο και το ημερολόγιο επιλέγει άμεσα την περίοδο που περιέχει τη συγκεκριμένη ημερομηνία. Το × επαναφέρει όλες τις ημερομηνίες. Παλαιότερες εγγραφές χωρίς το νέο πεδίο χρησιμοποιούν προσωρινά την ημερομηνία επιτροπής μέχρι να αποθηκευτούν ξανά.
9. Στις **Αναφορές**, επιλέξτε ιατρό ή εταιρεία για drill-down. Τα φίλτρα διατηρούνται μεταξύ ενοτήτων· το «Καθαρισμός» τα αφαιρεί. Το φίλτρο εταιρείας περιορίζει τα οικονομικά σύνολα στις γραμμές της επιλεγμένης εταιρείας, ενώ η λίστα περιστατικών δείχνει ολόκληρο το περιστατικό.
10. Η **Εξαγωγή CSV** εξάγει τις αναλυτικές γραμμές εταιρειών που αντιστοιχούν στα φίλτρα, με διαχωριστικό `;` και UTF-8 BOM. Περιλαμβάνει ημερομηνία περιστατικού και επιτροπής. Δεν περιλαμβάνει PDF ή περιστατικά που δεν έχουν ακόμη εταιρείες. Δεν είναι πλήρες backup.

## Κανόνες ποσών και καταστάσεων

Όλα τα ποσά αποθηκεύονται ως **ακέραια λεπτά**. Στις φόρμες επιτρέπεται κόμμα ή τελεία για δεκαδικά, έως δύο δεκαδικά ψηφία, χωρίς διαχωριστικό χιλιάδων. Το όριο ανά ποσό είναι €100.000.000. Δεν επιτρέπονται αρνητικά ποσά ή `P > C`.

Η κατανομή Plafond χρησιμοποιεί largest remainder: αρχικά ακέραιο κάτω μέρος κάθε αναλογίας και μετά ένα λεπτό στις μεγαλύτερες δεκαδικές διαφορές. Στις ισοπαλίες προηγείται η σειρά εταιρειών στη φόρμα. Η αριθμητική χρησιμοποιεί BigInt στο frontend και numeric/bigint στη βάση. Δεν υπάρχουν χαμένα λεπτά ούτε ανεξάρτητες στρογγυλοποιήσεις που αλλοιώνουν το σύνολο.

| Κατάσταση | Κανόνας, κατά σειρά προτεραιότητας |
|---|---|
| Κλειστό με διαφορά | Υπάρχει αιτιολογία και πραγματική διαφορά κάλυψης |
| Νέο | Δεν υπάρχουν εταιρείες· επιτρέπονται μόνο μηδενικά ποσά |
| Ολοκληρωμένο | Όλες οι εταιρείες «Παραλήφθηκε», παραληφθέν = αίτημα σε κάθε εταιρεία, και σύνολο παραληφθέντων = `C−P` |
| Μερικώς ολοκληρωμένο | Υπάρχει παραλαβή ή εταιρεία «Παραλήφθηκε», αλλά δεν πληρούνται τα κριτήρια ολοκλήρωσης |
| Αναμονή πιστωτικών | Υπάρχει εταιρεία «Ζητήθηκε» χωρίς παραλαβή |
| Προς αίτηση | Υπάρχουν εταιρείες αλλά δεν έχει ξεκινήσει αίτημα |

Το ποσό που παραλήφθηκε δεν μπορεί να υπερβαίνει το αίτημα, και το αίτημα/η πρόταση δεν μπορούν να υπερβαίνουν το κόστος της εταιρείας. Αίτημα απαιτεί ημερομηνία· παραλαβή απαιτεί ημερομηνία και αριθμό πιστωτικού. Οι ημερομηνίες πρέπει να ακολουθούν περιστατικό → επιτροπή → αίτημα → παραλαβή.

**Dashboard:** κόστος υλικών, σύνολο προτάσεων προς ανάκτηση, ζητηθέντα μόνο για αιτήματα που έγιναν, πραγματικά παραληφθέντα και ανοιχτά υπόλοιπα. Τα ανοιχτά υπόλοιπα είναι η πρόταση για «Προς αίτηση» και `ζητηθέν−παραληφθέν` για τα υπόλοιπα. Τα «Κλειστό με διαφορά» αποκλείονται από τα εκκρεμή, αλλά παραμένουν στα συνολικά ποσά και στη διαφορά κάλυψης. Η αναμονή μετριέται σε ημερολογιακές ημέρες από το αίτημα· άνω των 30 ημερών επισημαίνεται.

## Δομή και ασφάλεια

- `src/domain.js`: καθαροί υπολογισμοί, validation, αυτόματο status.
- `src/app.js`, `src/style.css`: ελληνικό responsive UI.
- `src/data.js`: Supabase REST/Auth/Storage. Auth tokens μόνο στο sessionStorage της καρτέλας, ανανέωση token πριν τη λήξη. Δεν αποθηκεύονται κωδικοί χρήστη.
- `mc_members`: εγκεκριμένα ενεργά μέλη· εγγραφή μόνο από διαχειριστή.
- `mc_companies`: μητρώο προμηθευτών με μοναδική επωνυμία.
- `mc_cases`: μία εγγραφή ανά περιστατικό με `payload` JSONB που περιλαμβάνει τις γραμμές εταιρειών. Αυτή η δομή επιτρέπει ατομική αποθήκευση/έλεγχο ολόκληρου του περιστατικού χωρίς ενδιάμεσα ασυνεπή αθροίσματα. Το trigger ελέγχει και την ύπαρξη κάθε εταιρείας. Δεν υπάρχει διαγραφή εταιρειών από την εφαρμογή.
- `mc_save_case`: αποθήκευση με έλεγχο έκδοσης. Αν κάποιος άλλος αποθήκευσε πρώτος, η αλλαγή απορρίπτεται και η φόρμα παραμένει διαθέσιμη για αντιγραφή των αλλαγών.
- `mc_cases.history`: προηγούμενα payloads, έκδοση, χρόνος και χρήστης, που διατηρούνται από το trigger. Το ιστορικό δεν φορτώνεται στη λίστα και δεν έχει ξεχωριστή οθόνη στο v1. Δεν είναι σύστημα καταγραφής προσβάσεων/αναγνώσεων.
- `mc-documents`: ιδιωτικό bucket, μόνο PDF έως 10 MB, τυχαία ονόματα UUID, signed URLs 60 δευτερολέπτων. Αντικατάσταση δημιουργεί νέο αντικείμενο· το παλιό παραμένει για το ιστορικό. Μη συνδεδεμένα uploads από αποτυχημένη αποθήκευση χρειάζονται περιοδικό διοικητικό cleanup μετά από έλεγχο τρέχοντος payload και ιστορικού. Ο client ελέγχει την επικεφαλίδα `%PDF-`, όχι πλήρες antivirus.
- RLS σε όλα τα tables· οι πολιτικές ελέγχουν ενεργή συμμετοχή στη βάση σε κάθε αίτημα. Οι SQL functions είναι `SECURITY INVOKER`, με κενό `search_path`. Καμία πολιτική επιτρέπει δημόσια πρόσβαση ή διαγραφή.

### Όρια v1

Μία συγκεντρωτική εγγραφή πιστωτικού ανά εταιρεία/περιστατικό, με ποσό/ημερομηνία/αριθμό και ένα τρέχον PDF. Για περισσότερα παραστατικά καταγράψτε το συνολικό ποσό και τις λεπτομέρειες στις σημειώσεις· πλήρες μητρώο πολλαπλών παραστατικών είναι επόμενη επέκταση. Τα φίλτρα και οι αναφορές υπολογίζονται στον client· για μεγάλο όγκο δεδομένων χρειάζεται server-side αναζήτηση/aggregation. Δεν περιλαμβάνονται αυτόματη αποστολή email, OCR αποφάσεων, διασύνδεση ERP ή ανάθεση διαφορετικών ρόλων ανά χρήστη. Το πλήρες backup αφορά τόσο τη βάση όσο και τα Storage objects και ρυθμίζεται στο νέο Supabase project.

## Έλεγχοι

```sh
node --test tests/domain.test.mjs
```

Για το SQL smoke test σε απομονωμένο PostgreSQL/WASM runtime εγκαταστήστε προσωρινά `@electric-sql/pglite@0.5.8` και τρέξτε `node tests/postgres-smoke.mjs`. Εναλλακτικά ορίστε `PGLITE_MODULE` στο file URL του `dist/index.js` μιας υπάρχουσας εγκατάστασης. Το test προσομοιώνει τα schemas Auth/Storage· δεν συνδέεται σε απομακρυσμένη βάση.

Δείτε `TESTING.md` για τα αποτελέσματα και τους ελέγχους που μένουν στο live project.

Επίσημες αναφορές: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage access control](https://supabase.com/docs/guides/storage/security/access-control), [Supabase Auth](https://supabase.com/docs/reference/javascript/auth-signinwithpassword).
